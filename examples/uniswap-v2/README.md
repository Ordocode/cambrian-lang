# Uniswap V2 — Cambrian on EVM

A Cambrian re-expression of [Uniswap V2 Core](https://github.com/Uniswap/v2-core)
(`UniswapV2Pair`, `UniswapV2Factory`, the ERC20 LP token + a separate
test ERC20), pinned to commit `6a9e7c97860676e0992f22a49665760444c1cdf5`
on `Uniswap/v2-core`. Targets EVM. Mirrors the structure of
`examples/governor/` and demonstrates:

- **2-`identity` deterministic CREATE2 addresses.** `UniswapV2Pair` has
  `identity { token0: address, token1: address }` — the first fixture in
  the repo to exercise CREATE2 with N>1 identity fields. Every cross-
  contract reference (`Pair.address(t0, t1)`) resolves to the same
  predicted address that `CambrianFactory.deployUniswapV2Pair(t0, t1)`
  actually deploys to.
- **Multi-instance test ERC20.** `ERC20` has `identity { token_id: u8 }`
  so we can deterministically deploy two distinct token contracts as
  the wrapped pair, both predicted off-chain by `ERC20.address(0)` /
  `ERC20.address(1)`.
- **Phased routes with cross-contract `var` capture on both tokens.**
  `mint`, `burn`, and `swap` all read `balanceOf(sys::address)` off
  `token0` and `token1` synchronously in their `read:` / `callback:`
  phases, then gate later phases on the captured values via per-phase
  `where` clauses (the K-invariant lives on the `check:` phase of
  `swap`).
- **`.fold(...)` over a Range** for Babylonian sqrt — the canonical
  Uniswap V2 use case for accumulator loops, lowered to an imperative
  Solidity for-loop with a single scalar accumulator (Phase 1 of this
  delivery introduced the `.fold` lowering on EVM; see
  `contracts/fold_evm.cam` for the unit fixture).
- **Flash-swap callbacks.** The `swap(...)` route's `callback:` phase
  threads `data: CamData` straight into the named send so the flash
  callee (a plain Solidity `FlashCallback.sol` sink under
  `ref/target/`) receives the original calldata. Repayment happens from
  inside the callback; the K-invariant on the `check:` phase rejects
  non-repaying flash swaps with `throw 203`.
- **Member-centric state.** Reserves, balances, allowances, pair
  registry, fee config — all updated in `in route(...) =>` member
  transforms, no `_beforeTokenTransfer`-style hook indirection.
- **`hashOf(...)`** for the `(min(t0, t1), max(t0, t1))` pair key —
  lowers to `keccak256(abi.encode(...))` on EVM.

The reference Solidity lives in `ref/`; the Cambrian translation lives
in this directory. See [PLAN.md](PLAN.md) for the design and the
Uniswap↔Cambrian recipe summary.

All three invariant fixtures (the singleton-shaped factory invariant
plus the two identity-bearing entity invariants for `ERC20` and
`UniswapV2Pair`) are exercised end-to-end now that **G-U9** is closed
— `with { ... }` clauses on the invariant body seed the constructor's
identity arguments before each fuzzer run.

## Reproduce

```bash
# 1. Transpile to Solidity + Foundry tests.
cargo run -p cambrian-transpiler --release -- \
    --project examples/uniswap-v2/project.yaml

# 2. Build and run Foundry tests (unit + fuzz + invariants).
cd examples/uniswap-v2/build
bash setup.sh        # installs forge-std, copies FlashCallback.sol, etc.
forge build
forge test -vv
```

Lean build (optional): `examples/uniswap-v2/project.lean.yaml`.

## Gap log (`G-Un`)

All ten Phase-2 risks are closed. The log is now a **regression-fixture
index** — each row points at the surface that lifted the gap, so any
future regression in those areas should re-fail this example. Full
table with notes lives in [PLAN.md](PLAN.md):

- **G-U1**: `permit()` / EIP-2612 — `evm::ecrecover` /
  `evm::keccak256Packed` intrinsics + `m_nonces` member +
  EIP-712 helpers in `ERC20.cam`.
- **G-U2**: cumulative-price oracle — `+%` / `-%` / `*%` lower to
  `_wadd` / `_wsub` / `_wmul` `unchecked` helpers; `m_price0/1_cumulative_last`
  on `UniswapV2Pair`.
- **G-U3**: `Vec<T>.push` in member transforms — `m_all_pairs: Vec<address>`
  matches OZ `address[] public allPairs;`.
- **G-U4**: 2-identity CREATE2 — first fixture to deploy with N=2
  identity members.
- **G-U5**: cross-contract `var` capture in state-writing routes —
  `mint` / `burn` `read:` phase.
- **G-U6**: 3-phase `swap` — `optimistic: → callback: → check:` with
  K-invariant.
- **G-U7**: address-shaped hex literal inference — `0x{40 hex}` and
  zero-padded `0x{64 hex}` infer as `address` and lower through
  `address(uint160(uint256(0x…)))`.
- **G-U8**: per-transform `let` scoping — every transform body that
  introduces a `let` (or has aliased route params) is wrapped in its
  own `{ … }` so `let pair = …` can be reused across sibling
  transforms.
- **G-U9**: identity-member seeding via `with { ... }` on invariants —
  `ERC20.invariant.cam` and `UniswapV2Pair.invariant.cam` exercise it
  end-to-end.
