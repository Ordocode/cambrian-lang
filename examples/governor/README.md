# Governor — Cambrian on EVM

A Cambrian re-expression of OpenZeppelin's governance suite (`Governor`,
`TimelockController`, `ERC20Votes`, pinned to OZ `v5.0.2`) targeting
EVM. Demonstrates:

- Deterministic CREATE2 addresses with the auto-generated
  `CambrianFactory`.
- Member-centric state and the `from <member|Entity(...)> [: throw N]`
  sender-check idiom (used by `TimelockController` for proposer /
  executor / canceller roles and by `Governor.cancel` for admin gating).
- Cross-target `sys::*` reads (`sys::timestamp` etc.) and the reserved
  `evm::` namespace for state-changing intrinsics.
- `enum` + `match` state machines (`OpState`, `ProposalState`).
- EVM `var` capture across phases (used in `Governor.castVote` to pull
  the caller's voting power off the token contract before tallying)
  plus per-phase `where` clauses for SSTORE-after-precondition ordering.
- `hashOf(...)` for proposal/operation ids — lowers to
  `keccak256(abi.encode(...))` on EVM.
- `data: CamData` parameters on routes and on `~> target with { data }`
  named sends.

The reference Solidity lives in `ref/`; the Cambrian translation lives
in this directory. See [PLAN.md](PLAN.md) for the design and the
OZ↔Cambrian recipe summary.

## Reproduce

```bash
# 1. Transpile to Solidity + Foundry tests.
cargo run -p cambrian-transpiler --release -- \
    --project examples/governor/project.yaml

# 2. Build and run Foundry tests (unit + fuzz + invariants).
cd examples/governor/build
bash setup.sh        # installs forge-std, copies CounterTarget.sol, etc.
forge build
forge test -vv
```

Lean build (optional): `examples/governor/project.lean.yaml`.

## Out of scope (intentional simplifications vs OZ v5.0.2)

These are documented per-entity in the `.cam` file headers and tracked
in [PLAN.md](PLAN.md):

- **Snapshot-free voting.** `ERC20Votes` does not keep historical
  checkpoints; `Governor.castVote` reads the caller's *current*
  `getVotes(...)`, not `getPastVotes(snapshot)`.
- **Single-target proposals / single-target ops.** No `address[]
  targets` arrays anywhere — the dynamic-array-arg gap is recorded as
  a future feature.
- **Single role-holder per role.** `TimelockController` has one
  `m_proposer` / `m_executor` / `m_canceller`, not OZ's
  `bytes32 PROPOSER_ROLE` mapping. Multi-holder roles need a
  `from`-chain over `Vec<address>`.
- **No `castVoteBySig`** (would require `ecrecover` lowering).
- **Fixed quorum.** `m_quorum` is a constructor argument, not a
  fraction of total supply re-evaluated each block.
- **Wall-clock deadlines.** `m_proposal_deadline` is in
  `sys::timestamp` seconds, not block numbers.
- **Settle is a manual route**, not a `view` projection of the
  computed proposal state — keeps the state machine member-driven.
- **`Abstain` votes** roll into "neither for nor against".
- **Constructor-time `var` capture** is not yet supported, so
  `Governor.m_min_delay` is hard-coded to `0` instead of being read
  from the timelock at deploy time.
